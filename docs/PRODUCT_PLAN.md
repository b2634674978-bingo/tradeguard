# TradeGuard 产品方案

版本：v0.1 原型  
定位：外贸 / 跨境交易前的「风险提示层」

## 1. 一句话

在上样品、报价、垫款之前，用 30 秒查一查这个 WhatsApp 号码 / 公司有没有被同行报过；被骗之后，用 2 分钟把经历变成下一个人能查到的证据。

## 2. 背景与问题

外贸卖家、SOHO、采购代理在找客户和找货源时，反复遇到三类损失：

1. **骗样品 / 白嫖**：以「大客户」「先测试」为名索要免费样品、运费、设计稿，拿到后消失或换号；
2. **收款不发货**：定金/尾款付出后不发货、发假货、失联；
3. **拖欠与假水单**：收货后拖欠尾款，或用伪造付款水单骗放货。

现有应对方式的问题：

| 方式 | 问题 |
|---|---|
| 微信群 / 朋友圈提醒 | 消息沉底、无法检索、换个群就看不到 |
| 论坛黑名单 / Excel 表格 | 格式混乱、号码写法不统一、无法匹配换号 |
| 企业征信 | 只覆盖注册企业，覆盖不了个人号、马甲号、跨境外壳 |
| 平台投诉 | 只处理站内交易，站外 WhatsApp 交易无法覆盖 |

核心矛盾：**作恶成本低、信息不互通、查询成本高**。

## 3. 目标用户

- **主力**：2–20 人的外贸 SOHO / 小团队，WhatsApp 谈单，样品和定金压力大；
- **次主力**：跨境采购代理、货代、验厂服务商（既掌握信息，也有查询需求）；
- **早期采用者**：被同一伙人骗过两次以上、已经在群里做「人工黑名单」的人。

用户任务（JTBD）：

> 当一个新客户来要样品/谈大货时，我想快速判断他是不是惯犯，以便决定要不要投入样品、要不要改付款方式。

## 4. 产品原则

1. **风险提示，不是审判**：不出现「骗子」定论，使用「风险等级」「举报记录」「疑似信号」；
2. **证据优先**：聊天记录指纹、时间线、金额、多条独立举报，比情绪化描述更重要；
3. **单条封顶**：1 条未经交叉验证的举报最高「中风险」，降低误伤和报复性举报；
4. **可申诉**：每个号码、每条记录都能申诉；
5. **最小化存储**：不保存完整聊天，只存必要证据摘要；
6. **本地优先**：先证明有人用，再谈云端与网络效应。

## 5. 核心流程

### 5.1 上报

1. 用户上传 WhatsApp 导出的 .txt，或粘贴关键对话；
2. 系统解析：号码、发送者、时间范围、消息数、媒体数、风险信号（免费样品、假水单、失联、尾款等）；
3. 用户确认对方号码、公司、国家、问题类型、金额、经过、证据摘要；
4. 提交入库，生成号码档案。

### 5.2 查询

1. 输入号码 / 公司 / 联系人；
2. 精确号码 → 完整档案；尾号相同 → 提示「疑似换号」；名称命中 → 提示核实主体；
3. 展示：风险等级、分数、举报次数、涉及类型、最近活跃、金额、证据；
4. 无记录 → 明确提示「无记录 ≠ 可信」，并给出验厂、担保、分期付款建议。

### 5.3 复核与申诉

- 被举报人（或熟人）可提交申诉；
- 本地版本由库主人在「设置」复核；
- 团队版加入角色权限、审核 SLA、操作审计。

## 6. MVP 范围

**做**：

- WhatsApp .txt 解析（Android/iOS）；
- 号码归一、尾号匹配、公司名模糊查询；
- 上报表单 + 证据摘要 + 本地 SQLite；
- 风险评分与解释；
- 情报库筛选、CSV 导入导出、SQLite 备份；
- 申诉记录、演示数据、数据看板。

**不做（当前阶段）**：

- 不做公开网站 / 公开榜单（法律与舆论风险高）；
- 不做自动加好友、自动群发、自动抓取；
- 不接入非官方 WhatsApp 协议库；
- 不做真实身份认证与付费（先验证需求）；
- 不保存完整聊天原文与媒体文件。

## 7. 数据与风险模型

核心表：

- **reports**：一条举报（号码、公司、类型、金额、经过、证据、来源、可信度、状态）；
- **report_phones**：举报与号码的多对多索引；
- **appeals**：申诉；
- **meta**：初始化标记。

评分（0–100）：

- 举报次数：最高 40 分；
- 问题类型严重度：最高 30 分；
- 近 90 天活跃：12 分；近一年：6 分；
- 附带聊天记录：8 分；
- 金额 ≥5000：8 分；≥1000：5 分；
- 举报可信度：-3 到 +3；
- **单条记录封顶**：有聊天记录且可信度 ≥70 时最高 55 分（中风险）；仅文字描述最高 39 分（低风险）；
- ≥70 高风险，45–69 中风险，20–44 低风险，<20 关注。

所有加分项在界面展示，避免黑箱。

## 8. WhatsApp 接入策略

| 方案 | 可行性 | 平台条款风险 | 工作量 | 结论 |
|---|---|---|---|---|
| 手动导出 .txt 上传 | 高 | 无 | 低 | **MVP 采用** |
| Chrome 插件读取 web.whatsapp.com 当前聊天 | 中高 | 中（依赖 DOM，不做自动化） | 中 | Phase 2 |
| WhatsApp Business Cloud API | 高（仅企业号） | 低（官方） | 中高 | Phase 3，适合客服；拿不到历史私聊，不适合取证 |
| 非官方库（Baileys / whatsapp-web.js） | 中 | **高，可能封号** | 中 | 不推荐 |

插件设计见 [WHATSAPP_PLUGIN.md](WHATSAPP_PLUGIN.md)。

## 9. 冷启动

这是双边数据产品，最大的风险不是技术，是**没人报、没人查**。

建议路径：

1. **先做工具，再做网络**：给 30 个外贸 SOHO 免费本地版，换取 3 条真实上报；
2. **找「有名单的人」合作**：货代、验厂、外贸社群群主，他们已有 Excel 黑名单；
3. **举报有门槛**：必须登录（团队版）/ 提供聊天记录指纹 / 至少 10 字经过，降低灌水；
4. **查询即价值**：即使只有 100 条记录，只要能命中一次，用户就会留存；
5. **行业垂直切入**：先做单一品类（如保健品原料、美妆包材），同一批骗子跨品类作案，命中率更高；
6. **双向评价**：卖家评买家，买家也可评卖家，长期做成交易信用层。

## 10. 商业模式

- **免费**：本地版查询 + 每月有限上报；
- **订阅**：团队版（共享库、审核队列、权限、审计、API）；
- **插件**：按月订阅，WhatsApp 侧边栏一键查询；
- **合作**：货代 / 验厂 / 担保支付导流分成；
- **不卖数据**：数据是信任资产，出售会直接摧毁产品。

## 11. 指标

- 上报 → 查询转化率；
- 查询命中率（有记录 / 总查询）；
- 7 日 / 30 日留存；
- 每条举报被查询次数；
- 申诉率、误报率、复核时长；
- 单用户平均节省的样品成本（访谈估算）。

## 12. 路线图

- **Phase 1（当前）**：本地网页原型，验证「上传聊天 → 查询」闭环；
- **Phase 2**：插件 + 本地服务 API；团队共享库（可选云端）；
- **Phase 3**：审核、身份、权限、审计、计费；
- **Phase 4**：与交易流程（担保、物流、验厂）集成。

## 13. 主要风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 法律 | 名誉权、个人信息、诽谤 | 不公开、证据制、申诉、单条封顶、律师审阅 |
| 冷启动 | 没数据就没人查 | 垂直行业 + 种子用户 + 导入现有 Excel |
| 恶意举报 | 同行抹黑、报复 | 记录指纹、可信度、审核、限流、申诉 |
| 平台依赖 | WhatsApp DOM/条款变化 | 手动导出兜底；官方 API 优先 |
| 隐私 | 聊天含敏感信息 | 本地解析、最小化、脱敏、删除权 |

## 14. 与现有产品的差异

- 比微信群/Excel：可检索、可匹配换号、有证据结构；
- 比企业征信：覆盖个人号、马甲号、跨境外壳；
- 比公开黑名单：私密、可申诉、单条封顶，法律风险更低；
- 比平台投诉：覆盖站外 WhatsApp 交易。
