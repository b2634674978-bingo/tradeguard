# TradeGuard · 市场调研（外部）

> 结论优先。【查证】附来源；【判断】为未逐页核实的经验推断。
> 例外：Wikipedia、Trustpilot、ScamAdviser、Meta 官方文档当前不可访问，判断已标注。

## 0. 五条结论

1. **“公开骗子黑名单”是明确的法律雷区。** 广州互联网法院“反恶”案已判：平台删除全部涉案个人信息 + 首页连续 30 日道歉，即使信息已打星、仅付费会员可见、内容由商家上传。【查证】
2. **空白不在企业征信，而在跨境个人/小 B 的 WhatsApp 号码信誉。** 企查查/天眼查只覆盖工商与司法公开数据，覆盖不到境外买家手机号。【判断】
3. **产品形态应是“风险分 + 结构化事件 + 证据可信度”，不是“名单”。** 中性标签、聚合展示、限定可见是对抗诽谤的核心。
4. **MVP 只做手动导出 txt 本地解析；浏览器插件二期；Cloud API 不适用于取证；非官方库不碰。**
5. **冷启动：免费查询 + 邀请制上报 + 行业联盟供数；向需求侧（货代/验厂/采购代理）收费，不向受害者收上报费。**

## 1. 现有同类与失败原因

| 类型 | 代表 | 解决什么 | 缺什么 / 为何没做大 |
|---|---|---|---|
| 外贸圈名单 | 论坛帖、QQ/微信群、Excel 表 | 熟人圈曝光 | 不可检索、易过期、无申诉→误伤后反被起诉；无收入【判断】 |
| 域名信誉 | ScamAdviser | 自动信号给站点打分 | 不覆盖 WhatsApp 个人号【判断，站点不可达】 |
| 评价平台 | Trustpilot | 评价 + 举报 + 企业回复 | 基于商户页，非个人号码；刷评争议【判断，站点不可达】 |
| 号码识别 | Whoscall / Truecaller | 号码库 + 众包标记 + 企业号码认证 | 依赖运营商/数据规模，中国外贸场景弱【查证：whoscall.com 功能页】 |
| 企业征信 | 企查查 / 天眼查 | 工商、司法、失信、关联关系 | 只聚合公开记录；不覆盖境外个人买家【查证：qcc.com】 |

**关键教训**：企查查类靠“转述官方记录”规避名誉风险；UGC 指控 + 公开点名是最高风险组合。外贸圈名单没做大，根因是**无审核、无申诉、无变现**。

## 2. 防恶意举报与冷启动

**证据分级**（决定是否计分）：A 级＝聊天原文 + 付款/物流/合同可交叉验证，满分；B 级＝聊天 + 单方凭证（转账截图），半分；C 级＝仅口述或单一截图，入库不计分。

**机制**：上报实名 + 手机验证；同一号码需 ≥2 个独立来源在 30 天内举报才计入；举报人按历史准确率加权；被举报人 7 日内可申诉、可下架；只展示聚合分与中性标签（“多方投诉未履约”），**禁用“骗子/欺诈”**；不公开完整聊天与举报人身份；查询需登录 + 限速；定期复核与时效衰减。

**冷启动**：选 1–2 个品类/航线（如义乌→中东），20–50 名种子用户；先“查询免费、上报邀请制”；与货代、验厂、外贸社群做联盟，用查询额度换数据。

## 3. WhatsApp 导出格式与接入

**格式差异【查证】**：iOS 形如 [24/10/24, 9:18:35 AM] 张三: 内容，含窄不换行空格 U+202F 与不可见 LRM U+200E；Android 形如 4/11/25, 9:17:58 PM ~ 张三: 内容，时间与发送者间可能带 ~；旧版/其他语言形如 15.04.2016, 15:04 - 张三: 内容。日期顺序与 12/24 小时制随语言变化；需过滤媒体占位符（image omitted、<Media omitted>）、系统消息与多行消息。

| 接入方式 | 可行性 | ToS / 封号风险 | 工作量 |
|---|---|---|---|
| 手动导出上传 | 高，零依赖，可全本地 | 无 | 2–4 人日 |
| 浏览器插件读 web.whatsapp.com DOM | 中，仅当前账号已同步会话，DOM 易变 | 灰色，属未授权客户端 | 2–3 周 |
| WhatsApp Business Cloud API | 低：拿不到历史私聊，需 Business 账号 + opt-in + 模板 | 合规 | 不适用于取证 |
| Baileys / whatsapp-web.js | 技术可行 | **明确违反“不允许非官方客户端”，封号风险实存** | 1–2 周 |

whatsapp-web.js 官方指南原文：not guaranteed you will not be blocked… WhatsApp does not allow bots or unofficial clients on their platform。【查证】Baileys 亦声明与 WhatsApp 无关联、不认可违反 ToS 的用法。【查证】

**MVP 推荐**：手动导出 txt → 浏览器内 JS 解析（不上传服务器）→ 本地 SQLite 存号码哈希与结构化事件。插件二期只做“用户点击后抓取当前会话”，绝不后台自动同步——这既是技术选择，也是免责设计。

## 4. 法律与合规

- **中国**：手机号属个人信息（PIPL 第 4 条），处理需同意或其他合法性基础（第 13 条）、须告知（第 17 条）。“反恶”案认定：打星后仍可识别 → 仍属个人信息；与“恶人/欺诈”等负面词结合 → 侵害名誉权（民法典 1024、1034、1035）。针对企业还可能触及刑法 221 损害商业信誉罪【判断】。
- **GDPR**：欧盟号码即个人数据；可用正当利益（Art 6(1)(f)）+ 透明告知（Art 14），但必须提供删除权（Art 17）与异议权。永久黑名单与“被遗忘权”直接冲突 → 设保留期与申诉删除。
- **美国**：Section 230 保护平台不因用户内容被视为发布者，但**不保护知识产权、不适用于非美国主体**；fraudster 类标签可能构成 per se defamation【判断】。

**降险设计**（按性价比排序）：① 明示“风险提示，非事实认定”；② 被举报人申诉与删除通道（对齐民法典 1195 通知—删除）；③ 来源可信度分级；④ 只存必要证据（哈希 + 摘要，不存完整聊天）；⑤ 访问控制与审计日志；⑥ 聚合分而非原始指控。

## 5. 商业模式

免费查询（拉需求）→ 付费深度报告 / API（货代、验厂、采购代理、跨境平台）→ 团队版（多人查询、导出、监控）→ 行业联盟共建（协会/服务商供数换额度）→ 征信数据合作。

**冷启动最优：免费查询 + 联盟供数 + 需求侧订阅。** 不要向上报者收费——会直接杀死供给；也不要做“付费曝光位”，那正是“反恶”案的败诉模式。
