# 2026-10-28 第二轮：Postgres 持久化 + 安全回归修复

本轮目标：解决「Render 免费版重启即清空数据」这个根问题，并修复上一轮遗留的两处回归。

---

## 1. 数据层改造：一套 SQL，两种引擎

### 新增 `tradeguard/dbdriver.py`（方言兼容层）

| 差异点 | SQLite 写法 | Postgres 写法 | 处理方式 |
|---|---|---|---|
| 占位符 | `?` | `%s` | 逐字符扫描翻译，跳过单引号字面量 |
| 忽略重复插入 | `INSERT OR IGNORE` | `ON CONFLICT DO NOTHING` | 语句重写 |
| 覆盖写入 | `INSERT OR REPLACE` | `ON CONFLICT (key) DO UPDATE SET ...` | 按表声明冲突目标（meta → key） |
| 自增主键 | `INTEGER PRIMARY KEY AUTOINCREMENT` | `INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | 建表模板变量 |
| 取新插入 id | `cursor.lastrowid` | `INSERT ... RETURNING id` | `conn.insert_id()` |
| 二进制 | `BLOB` | `BYTEA` | 建表模板变量；参数直接传 `bytes` |
| 列名查询 | `PRAGMA table_info` | `information_schema.columns` | `backend.columns()` |
| 浮点 | `REAL` | `DOUBLE PRECISION` | 建表模板变量 |

### 连接池

Postgres 每次请求新建 TCP + TLS 连接在 Supabase 上要 100ms 量级，而 Streamlit 一次页面渲染会发起十余次查询，因此：

- 懒创建、LIFO 复用，上限 `TRADEGUARD_PG_POOL`（默认 4）；
- 取用前 `SELECT 1` 探活，断连自动丢弃重建；
- 回滚失败（连接已死）的连接不归还池。

### DSN 归一化

- `postgres://` → `postgresql://`（Render/Heroku 下发的是前者，psycopg 只认后者）；
- 剥离 `pgbouncer` / `connection_limit` / `pool_timeout` 等 PgBouncer 私有参数（透传会导致“无效连接选项”）；
- 端口 6543 或 `pgbouncer=true`（Supabase 事务模式）时自动 `prepare_threshold=None`，关闭服务端预处理语句，避免 `prepared statement already exists`。

### `database.py` 的变化

业务逻辑与 SQL 一行未改，只替换底层：

- 建表脚本改为方言模板 + 语句列表（不再依赖 `executescript`）；
- 两处 `lastrowid` 改用 `conn.insert_id()`；
- 去掉 `sqlite3.Binary()`（`bytes` 两种引擎都接受）；
- 新增 `engine` / `is_postgres` / `supports_file_backup` / `location` 属性供 UI 使用；
- 新增 `restore_from_bytes()`（带 SQLite 文件头校验）与 `export_rows()`；
- `backup_bytes()` 在 Postgres 下显式报错，不再静默写入无意义文件。

**关键约定：显式传 `path` 时强制 SQLite**，因此本地开发与全部单元测试不受 `DATABASE_URL` 影响。

## 4. 顺手修掉的两个既有缺陷

### 4.1 管理员密码被硬编码（安全）

`tradeguard/auth.py` 中 `_admin_password()` 返回硬编码的 `TradeGuard2026!***（已失效，勿再使用）`，与上一轮 changelog 声明的「已移除硬编码密码」不一致——**任何看到公开仓库的人都能登录管理员**，可审核、驳回、清空、导出全部数据。

已恢复为只从 Secrets / 环境变量读取：

1. `st.secrets["ADMIN_PASSWORD"]`
2. 环境变量 `ADMIN_PASSWORD`
3. 环境变量 `TRADEGUARD_ADMIN_PASSWORD`

> **上线前必须**在 Render Environment 或 Streamlit Secrets 配置 `ADMIN_PASSWORD`，否则管理员入口显示「未配置」，任何人都无法管理数据（宁可只读，也不能留后门）。

### 4.2 聊天记录日期解析不支持美式格式

`chat_parser._parse_timestamp()` 固定按「日/月/年」解析，遇到 WhatsApp 美式导出 `12/31/25`（月=12、日=31）会因月份 31 越界返回 `None`，导致时间范围与时效性评分失真。已改为：第二段 > 12 时按「月/日/年」解析，其余保持「日/月/年」优先。

同时补充了 4 个英文免费样品话术关键词（`sample is free`、`sample should be free`、`samples are free`、`sample must be free`），此前 `No, sample should be free.` 这类表达检测不到。

## 8. 真实 Postgres 验证（2026-10-28 11:48–12:05）

已用 Neon 真实实例（PostgreSQL 18.6，AWS us-west-2 Oregon，pooled 端点）完成验证，此前「无法本地起真库」的缺口已闭合。

### 8.1 发现并修复一处 SQL 方言缺陷

`_reports_for_phone()` 原为：

```sql
SELECT DISTINCT r.* FROM reports r
JOIN report_phones rp ON rp.report_id = r.id
WHERE rp.phone_norm = ?
ORDER BY COALESCE(r.incident_date, r.created_at) DESC
```

SQLite 允许 `DISTINCT` 查询按未出现在选择列表中的表达式排序；**Postgres 直接报错** `InvalidColumnReference: for SELECT DISTINCT, ORDER BY expressions must appear in select list`。

后果严重程度：`search()` 是所有号码查询的入口，这个错误会让**整个查询页在 Postgres 下 500**，而 SQLite 单测完全发现不了。

改为子查询写法（两引擎同构，且能走 `idx_report_phones_norm` 索引）：

```sql
SELECT r.* FROM reports r
WHERE r.status = 'approved'
  AND r.id IN (SELECT rp.report_id FROM report_phones rp WHERE rp.phone_norm = ?)
ORDER BY COALESCE(r.incident_date, r.created_at) DESC
```

## 7. 已知边界

## 8. 管理员门禁修正

### 8.1 问题

本地运行看不到任何「管理员登录」入口。原因不在样式，而在 `auth.py` 的判断依据：

```python
def is_admin() -> bool:
    if not PUBLIC_DEMO:      # 本地运行 PUBLIC_DEMO=False
        return True          # → 永远有全部权限
def login_widget():
    if not PUBLIC_DEMO:
        return               # → 登录框永远不渲染
```

门禁挂在「运行环境」上，而不是「有没有配密码」上。结果是：本地（或任何自建部署）根本没有登录环节，谁能打开页面谁就是管理员；反过来，公开部署漏配密码则只能只读，没有补救入口。

### 8.2 改法

- **判定依据改为密码**：`admin_required() = 配置了 ADMIN_PASSWORD or 公开部署`。配了密码，任何环境都要登录；没配密码，本地开放、公开部署强制只读。
- **登录区常驻**：「设置与合规」顶部始终渲染管理员区块，三种状态各有明确文案（本地免登录 / 未配置密码只读 / 登录框）。侧边栏增加权限提示，未登录时直接指路。
- **登录改用回调**：`st.button(on_click=...)` 替代脚本中段的 `st.rerun()`。之前登录后会出现「管理区」与「公开只读模式」同屏的中间态。
- **拆分「管理员」与「访客视角」**：新增 `public_viewer()`（公开部署且未登录）。脱敏、截图公开、新举报进待审核队列只跟访客视角有关；本地哪怕配了密码，查询与上报仍按完整数据、提交即收录，不会因为「加个密码」把原有工作流改掉。

### 8.3 顺带修掉的测试污染

`tests/conftest.py` 之前不隔离 Secrets。开发者一旦在 `.streamlit/secrets.toml` 里配了 `DATABASE_URL`，`pytest` 里的 AppTest 就会连上**真实线上库**写数据；配了 `ADMIN_PASSWORD` 又会把页面变成只读，测试结果取决于本机配置。现在 autouse 夹具统一钉死为「本地 SQLite + 无管理员密码」。

### 8.4 验证

- `pytest`：46 passed（新增 5 项门禁用例：本地免登录、配密码后出现登录框、错误密码被拒、登录解锁管理区且不残留只读区块、公开部署漏配密码只读）
- 浏览器实测三态：未登录 → 只有登录框 + 只读提示；登录 → 只有管理区（含危险操作、批量导入）；退出 → 回到只读。三态互斥，无重复渲染。

## 9. 前后台分离（公开站 / 管理后台）

### 9.1 动机

这个产品的使用者是普通外贸业务员，他们只需要「查号码、看风险、报一单」。
把备份、导入、清空、存储引擎这些运维内容摆在同一个导航里，既吓人也不安全——
任何人都能从侧边栏点进「设置与合规」看到后台界面（哪怕被锁）。

### 9.2 结构

| | 公开站（默认） | 管理后台（`?admin=1`） |
|---|---|---|
| 导航 | 查询验证 / 上报记录 / 情报库 / 数据看板 / 帮助与合规 | 多一项「管理后台」 |
| 内容 | 用法三步、数据来源、号码脱敏说明、申诉指引、合规边界 | 待审核、数据与备份、批量导入、申诉队列、危险操作 |
| 侧边栏 | 只有统计（举报/号码）与脱敏开关 | 追加存储引擎与登录状态 |

- 入口：帮助页底部一个不起眼的「管理员入口」链接，`href="?admin=1"`，`target="_self"`；
  登录后 query 参数仍在，刷新不会掉出后台导航。
- 未登录时后台只剩一个登录框和一句说明，不渲染任何按钮；未配密码时整页写明「没人能管理数据」。

### 9.3 连带调整

- `settings.py` 拆成 `help.py`（公开说明）与 `admin.py`（后台，用 `st.tabs` 分五个区块）；
- 申诉入口不再要求管理员：被举报方本来就是普通用户，原先把入口锁在管理员后面，
  与合规文里写的「每条记录都提供申诉入口」自相矛盾。现在所有人在查询结果里都能提交；
- 侧边栏不再向访客暴露存储引擎、部署形态；「待复核」计数只在后台显示；
- 后台统计改用文本行（`stat_strip` 是给深色侧边栏设计的，放到主区域对比度不足）。

### 9.4 验证

- `pytest`：49 passed（前台五页逐页断言「无登录框 / 无备份 / 无危险操作」，后台 5 项门禁用例）
- 浏览器实测：根路径无管理入口；帮助页 → 管理员入口 → `?admin=1` → 登录 → 五个标签页齐备；
  普通用户查询记录后可见申诉表单，页面无任何后台元素。
